## 2024-05-24 - [CryptoManager Fail-Secure Mechanism & Key Size]
**Vulnerability:** The application's local encryption utility `CryptoManager.kt` could crash the application due to unhandled exceptions like `AEADBadTagException` (if ciphertext tampered) or `IndexOutOfBoundsException` (if ciphertext too short) within `decrypt`. It also did not explicitly set key sizes during initial KeyStore AES generation.
**Learning:** Defensive layers are required within cryptographic utilities. Unhandled exceptions during data transformations expose the application to DoS attacks via malformed data.
**Prevention:** Always encapsulate `Cipher.doFinal` within `try/catch` and return safe defaults (e.g., `""`) to ensure the application fails securely without crashing or leaking sensitive stack traces. Explicitly specify `.setKeySize(256)` when generating keys using KeyGenParameterSpec.Builder to guarantee encryption strength.
